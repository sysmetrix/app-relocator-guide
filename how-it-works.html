AppRelocator 안내 사용 절차 지도 작동 원리

옮긴 앱은 대상 드라이브에서 실행되고 업데이트됩니다

AppRelocator 로 프로그램과 데이터를 D: 같은 대상 드라이브로 옮기면, 앱은 아무것도 바꾸지 않은 채 그대로 실행되고 새 파일과 업데이트도 대상 드라이브에 저장됩니다. 그 원리와 앱별 방식, 알아 둘 점, 그리고 지금까지 확인된 범위를 정리했습니다.

한 줄 답

네. 앱은 예전 경로(C:)를 그대로 열지만 Windows 가 그 경로를 대상 드라이브로 이어 주므로, 실행·저장·업데이트가 모두 대상 드라이브에서 일어납니다.

단, 업데이트가 연결을 깨는 드문 경우와 C: 에 조금 남는 것이 있어 아래 "알아 둘 점"을 함께 보세요.

업데이트가 지나가는 길

알아 둘 점

  1. 업데이트가 연결을 깨는 경우

    드물게 업데이트 프로그램이 폴더를 통째로 지우고 새로 만들면, 연결이 일반 폴더로 바뀌어 다시 C: 에 쌓입니다. 큰 업데이트 뒤에는 AppRelocator 의 진단·복구를 열어 보세요. "연결이 일반 폴더로 바뀜"이 보이면 버튼 하나로 다시 대상 드라이브로 연결합니다(그사이 생긴 파일은 지우지 않고 보관).

  2. C: 에 조금은 남습니다

    연결 자체(용량 0), 시작 메뉴 바로 가기, 레지스트리 등록 정보, Aside·ego 의 업데이트 서비스 폴더(Program Files (x86)\…\Updater, 수십 MB), 임시 파일. 용량의 대부분인 프로그램과 데이터는 대상 드라이브에 있습니다.

  3. 이전 사본을 지워야 C: 가 비워집니다

    옮긴 직후 원본은 .relocator-bak 으로 남습니다. 앱이 잘 되는지 확인한 뒤 기록 › 이전 사본 지우기. 지우기 전까지는 언제든 C: 로 되돌릴 수 있습니다.

  4. 외장(USB) 드라이브라면 연결해 두어야 합니다

    대상 드라이브가 분리되어 있으면 옮긴 앱은 실행되지 않습니다. 앱의 로그인 자동 실행은 끄고, 끝나면 드라이브 꺼내기로 분리하세요. 내장 드라이브라면 해당 없습니다.

  5. 속도는 대상 드라이브를 따릅니다

    느린 HDD·USB 로 옮기면 앱도 그만큼 느려집니다. SSD 끼리라면 차이가 거의 없습니다.

  6. 스토어 앱 본체는 Windows 가 거부할 수 있습니다

    Codex·Claude 처럼 시스템 서비스가 들어 있는 앱은 Windows 가 본체 이동을 막을 수 있습니다. 그래도 용량의 대부분은 데이터라서 데이터만 옮겨도 대부분의 공간이 확보됩니다. Claude 는 처음 설치할 때 대상 드라이브에 바로 설치할 수 있습니다.

확인

연결 만들기, 복사, 파일 수·크기 검증, 되돌리기, 중단 뒤 이어서 하기, 드라이브 문자 변경, 연결이 일반 폴더로 바뀐 경우의 복구 — 자동 테스트로 실제 파일 시스템에서 확인.

확인

Codex·Claude·Gemini·Aside·ego(lite) 의 설치 위치·데이터 폴더·실행 중 감지 — 실제 설치된 PC 에서 확인. 공식 설치 파일 주소와 게시자 서명 확인.

일부

프로그램 폴더 옮기기(Gemini·Aside·ego) — 옮길 계획(미리보기)과 관리자 권한 확인까지 확인. 실제 앱을 옮긴 뒤 실행해 보는 시험은 아직.

미확인

옮긴 뒤 앱의 자동 업데이트가 실제로 대상 드라이브에 새 버전을 쓰는지 — 다음 업데이트 때 진단·복구와 폴더 위치로 확인할 예정.

AppRelocator 는 각 앱의 파일을 고치지 않고 Windows 기본 기능(디렉터리 정션, 앱 저장소)만 사용합니다. Codex·ChatGPT 는 OpenAI, Claude 는 Anthropic, Gemini 는 Google, Aside 는 At Your Side, ego(lite) 는 Citro Labs 의 상표이며 AppRelocator 는 각 회사와 관련이 없습니다.
